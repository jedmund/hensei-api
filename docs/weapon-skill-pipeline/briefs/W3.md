# W3: stored sources

**Wave 1.** Depends on W0 (the `SourceStore` interface). Migration block `…12xxxx`. Branch `pipeline/W3-sources`. Issue label `pipeline:W3`.

## Goal

Every input the build needs is stored and hashed, so a build never calls the wiki. Fetching becomes one explicit step.

## Deliver

1. **`weapon_sources` table:**
   - columns: `weapon_id`, `kind` (`wiki_raw` | `expanded` | `transclusion` | `family_template`), `key` (page title), `body`, `sha256`, `fetched_at`, `page_kind` (`inline` | `series_template` | `key_determined`);
   - unique on `(weapon_id, kind, key)`. Family templates use a null `weapon_id`.
2. **`page_kind`** is set at fetch time from the page's template name: `{{Weapon/Common/<Series>…` means `series_template`; a key placeholder means `key_determined`. It replaces substring sniffing such as the `s1_desc=` check.
3. **`SourceStore`** (implementing W0's interface) backed by the table. `Granblue::Parsers::Wiki` gets a store mode:
   - `fetch` and `expand` read from the store;
   - during a build (`WeaponSkills.build_mode != "off"` or an explicit `offline: true`), a miss raises `SourceMissing` instead of calling the network.
4. **`granblue:fetch_weapon_sources [ids=] [stale_days=] [kind=]`:**
   - stores `wiki_raw`, the `expandtemplates` output for every series-template page (about 703), every transclusion and template page `WeaponParser` follows, and the 131 `Template:Weapon Skills/*` pages;
   - also updates `weapons.wiki_raw` and `wiki_raw_fetched_at`;
   - throttled, resumable, and reports failures;
   - **discovering transclusions:** the parser follows transcluded and template pages while parsing. Find them at fetch time with a recording store: run the structural parse once per weapon, inside the fetch task, through a store that fetches misses and records them. That's the fetch step, not a parse whose output is kept: roll back whatever it writes.
5. **Add `weapon_sources` to `WeaponSkills::CatalogueDump::TABLES`.** This is the one W0 file you may edit. The next catalogue dump then carries the sources, so other workstreams parse offline.
6. **The admin refetch** (`POST /weapons/:id/fetch_wiki`) and `WikiFetcher` write through the store.

## Owned files

- `lib/granblue/parsers/wiki.rb`, `app/services/granblue/wiki_fetcher.rb`, `lib/tasks/fetch_wiki.rake`
- `lib/weapon_skills/source_store/**`
- the new model, migration, task and specs

**Forbidden:** parser and extractor internals (W6 ports them), `key_skill_extractor.rb` (W5 adopts your store).

## Acceptance

- After a fetch on a pipeline database, every weapon with a page has its sources.
- A WebMock spec shows `EntityReparser` makes zero HTTP calls in offline mode.
- `skill_parity mode=full_reparse`, now offline, reproduces the frozen online diff in `data/weapon_skill_parity/full_reparse_2026-10-15.json`. Explain any difference on the issue; the wiki may have changed since. Don't re-run anything online to compare.

## Fetching

Your fetch task is the **only** sanctioned wiki access in this project. We never parse against the live wiki.
- Fetch once into your pipeline database.
- Post the counts on your issue.
- Tell the lead, who publishes a new catalogue dump from your database so other workstreams get the sources.

## Prod step

The lead does this after merge: run `bin/rails granblue:fetch_weapon_sources` on prod once, then publish a new catalogue dump.
