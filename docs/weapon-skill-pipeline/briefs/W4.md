# W4: goldens in CI

**Wave 1.** Depends on W0. Migration block `…13xxxx` (you shouldn't need one). Branch `pipeline/W4-goldens`. Issue label `pipeline:W4`.

## Goal

The golden panel references run in CI, with no prod copy needed.

## Deliver

1. **`granblue:export_golden_fixture shortcode=`** writes `spec/fixtures/goldens/<shortcode>.json`:
   - **party:** grid weapons (uncap, transcendence, awakening, keys, AX), summons, characters, job, accessories and blessings;
   - **embedded catalogue rows** those use: weapons, slots, versions, data and effects (version-linked, plus the canonical and family rows they resolve to), boost types, panel lines, summon auras, character skills;
   - **stripped:** user ids, usernames, edit keys, descriptions and any free text. A spec asserts none of those keys appear.
2. **`granblue:import_golden_fixture shortcode=`** loads a fixture into a database (tests and dev).
3. **`spec/requests/goldens_spec.rb`:** for each fixture with a reference in `data/panel_references/`, load it and run `Granblue::PanelValidator` for that reference. Each reference is its own example.
4. **Fixtures** for the parties that exist today: g0gpOT, P8fDVY, atSjtJ, F0MD7j (covers F0MD7j and F0MD7j_noarc), ZCoUJT, PWwPYz, wOF5LS, lCMBmU, SRiNSO.
5. **A loader seam in `PanelValidator`,** so it can validate a party passed in, not only one looked up by shortcode.

## Owned files

- `lib/tasks/golden_party.rake`
- `spec/fixtures/goldens/**`, `spec/requests/goldens_spec.rb`

## Acceptance

- Deleting a curated row from a fixture turns its example red. Show this in the PR, then revert it.
