# W0: contracts and tooling

**Owner:** the lead session. Sequential: everything else waits on this.

## Goal

Give every other workstream:
- the parity baseline and its comparison task;
- a database it can restore anywhere;
- the shared structs, overlay format and interfaces;
- the GitHub issues to report on.

## Deliver

1. **`granblue:skill_parity`** (`lib/tasks/skill_parity.rake`, `lib/weapon_skills/parity_snapshot.rb`):
   - **Default mode:** snapshot the current database and compare against `data/weapon_skill_parity/baseline.json`. Exits nonzero on any difference.
   - **Options:**
     - `write=true` refreshes the baseline;
     - `group=series` groups the diff by weapon series;
     - `mode=full_reparse` runs today's `EntityReparser` over every weapon in a rolled-back transaction, then diffs (needs network until W3);
     - `mode=extract` runs only the offline extractor.
   - **Diff output:** per version, which of gate, frame, data and effects changed, before and after. Also written to `data/weapon_skill_parity/last_diff.json` (gitignored).
   - **Baseline header:** the catalogue dump tag and the git SHA.
2. **`baseline.json`**, generated from a restored copy of the 2026-10-14 prod backup plus the curation sync from main.
3. **`granblue:export_catalogue_dump`:**
   - a `pg_dump -Fc -Z9 -O -x` of catalogue tables only: weapons, weapon series/variants, skills, the weapon-skill tables, families, boost types, panel lines, keys and key series, awakenings, stat modifiers, summons and their series/auras/calls, characters and their series/skills/versions/links, skill effects and values, charge attacks, jobs and job skills/accessories, raids and raid groups, bullets, Arcarum blessings, effects and statuses;
   - no users, parties, grids, collections, crews or OAuth;
   - a spec asserts the table allowlist.
   - Publish with `gh release create catalogue-YYYYMMDD -R jedmund/hensei-api <dump>`.
4. **`bin/setup-pipeline-db NAME`:**
   - creates `hensei_pipeline_NAME`, downloads the latest `catalogue-*` asset with `gh release download`, and restores it;
   - creates the remaining tables with `db:schema:load` for non-catalogue tables, then migrates;
   - runs `granblue:sync_weapon_skill_curation` and loads the golden fixtures if present.
   - Idempotent (drops and recreates).
5. **`lib/weapon_skills/build_result.rb`:** `Slot`, `Version` and `Row` structs with `identity`, plus specs.
6. **`docs/weapon-skill-pipeline/overlay-v2.md`** and `spec/lib/weapon_skills/overlay_schema_spec.rb`:
   - **operations:** v1 overrides and rows, plus `add_version`, `remove_version`, `gate` and `description`;
   - **layout:** per-series files `data/weapon_skill_curation/<series>.json` and `_canonical.json`;
   - **precedence.**
7. **`lib/weapon_skills/source_store.rb`:** the interface only (`fetch`, `put`, `SourceMissing`), with a null implementation. W3 implements it.
8. **The flag** `WEAPON_SKILL_BUILD` read in one place (`WeaponSkills.build_mode`).
9. **GitHub:** the tracking issue and one issue per W1–W5, each linking its brief.

## Prototype

The snapshot logic was prototyped on 2026-10-15. For each `WeaponSkillVersion` (with skill and slot), it records:
- `gate: [unlock_level, min_uncap, transcendence_stage]`;
- `frame: [resolved_modifier, resolved_series, resolved_size, multiplier_frame]`;
- `data: weapon_skill_data → [boost_type, formula_type, sl1, sl10, sl15, sl20, sl25, coefficient, aura_boostable]`;
- `effects: weapon_skill_effects → [boost_type, scaling_kind, value, per_copy_cap, total_cap, cap_formula, condition, series, aura_boostable]`.

Decimals become floats and rows are sorted. It runs in about 3 s.
