# W7: overlay v2 applier

**Wave 2.** Depends on W0 (overlay v2 format) and W2 (its pending fragments) being on `pipeline/integration`. Migration block `…16xxxx`. Branch `pipeline/W7-overlay`. Issue label `pipeline:W7`.

## Goal

The committed curation overlay becomes the only place for corrections, structural ones included. That retires the manifests and one-off data migrations that today's state depends on (see `docs/weapon-skill-pipeline/overlay-v2.md`).

## Deliver

1. **`Granblue::CurationSnapshot` reads v2:**
   - per-series files under `data/weapon_skill_curation/` plus `_canonical.json`;
   - keeps reading the v1 `data/weapon_skill_curation.json` until the split lands in the same PR.
   - Every file is validated with `WeaponSkills::OverlaySchema` before anything is applied. Any error aborts the sync.
2. **Structural ops**, in the order the overlay spec gives: `remove_version`, `add_version`, `gate`, `description` (writes W6c's columns; coordinate with the W6c agent), then overrides, suppressions and rows.
   - Each op is idempotent. A second sync changes nothing; spec it.
   - An op that matches nothing is reported, as unmatched rows are today.
3. **Export writes v2:** per-series files, sorted. The dev auto-export (`config/initializers/curation_auto_export.rb`, `Granblue::CurationAutoExport`) and the drift check (`granblue:weapon_skill_curation_drift`) follow.
4. **Split the v1 file** into the v2 layout, and fold in W2's `data/weapon_skill_curation/pending/*.json`.
5. **Retire the manifests:**
   - convert `db/data/manifests/skill_version_gates.json` into `gate` ops and `db/data/manifests/july_calculator_recovery.json` into overlay entries;
   - delete the manifests and update the migrations that read them, so they no-op when the manifest is gone (they've already run on prod);
   - update `docs/weapon-skill-curation.md`.
6. **The `CurationView` interface for W6b:** which boost types are curated or suppressed for a version identity. Agree it with the W6b agent.

## Owned files

- `app/services/granblue/curation_snapshot.rb`, `lib/tasks/weapon_skill_curation.rake`
- `config/initializers/curation_auto_export.rb`, `app/services/granblue/curation_auto_export.rb`
- `data/weapon_skill_curation/**`, `data/weapon_skill_curation.json`
- `db/data/manifests/skill_version_gates.json`, `db/data/manifests/july_calculator_recovery.json`
- the migrations that read those manifests (only to tolerate their absence)
- `docs/weapon-skill-curation.md`, specs

## Acceptance

- On a fresh pipeline database: sync, then `granblue:skill_parity` reports no differences.
- A second sync reports 0 created, 0 updated and no ops applied.
- The drift check is clean.
- Once W3's offline `full_reparse` exists: reparse, then sync, then parity leaves only the classified `parser` and `accept` differences from W2.
