# W1: safety fixes and fetch dates

**Wave 1.** Depends on W0. Migration block `…10xxxx`. Branch `pipeline/W1-safety`. Issue label `pipeline:W1`.

## Goal

- Close the live hazards that destroy or silently drop curation.
- Record when each entity's wikitext was fetched.

Parity must not change.

## Deliver

1. **Version editor.** `PATCH /weapon_skill_versions/:id` (`app/controllers/api/v1/weapon_skill_versions_controller.rb`):
   - permits `modifier_override`, `series_override`, `size_override` and `suppressed_boosts`, and stamps `overrides_edited_at`;
   - stops permitting the raw `skill_modifier`, `skill_series` and `skill_size`, which a reparse overwrites.
   - Request specs: editor role, a non-editor gets 403, and the edit survives `EntityReparser`.
2. **Web follow-up.** Check `hensei-svelte`'s weapon-skill version editor. If it sends the raw fields, open a hensei-web PR switching it to the override fields, and link it on the issue.
3. **`ExpandedWeaponSkillImporter.cleanup_garbled`** skips rows with `manually_edited_at`. Only the garbled version's generated rows are deleted; a version with curation is kept and reported.
4. **`WeaponSkillDescriptionExtractor.family_curve`** uses `resolved_modifier`, `resolved_series` and `resolved_size`, so a `modifier_override: "none"` version can't pick up a family curve.
5. **JSON loaders** (`lib/tasks/weapon_skill_data.rake`, `lib/tasks/weapon_skill_effects.rake`) scope every lookup to `weapon_skill_version_id: nil`.
6. **Integrity:**
   - **`Skill`:** `has_many :weapon_skill_versions` becomes `dependent: :restrict_with_error`.
   - **Data migration:** delete the 10 orphaned `weapon_skill_effects` (and any orphaned data).
   - **Schema migration:** foreign keys from `weapon_skill_data.weapon_skill_version_id` and `weapon_skill_effects.weapon_skill_version_id` to `weapon_skill_versions`, with `on_delete: :cascade`.
7. **Fetch dates.**
   - **Schema migration:**
     - `wiki_raw_fetched_at` (datetime) on `summons` and `characters`;
     - `wiki_raw_jp_fetched_at` on `weapons`, `summons` and `characters`.
     - `weapons.wiki_raw_fetched_at` already exists.
   - **Data migration:** set `2026-10-15 00:00 UTC` wherever the wikitext is present and the date is null. Keep weapons' existing real dates (1,858 rows, 2026-06-17 onward).
   - **Writers:**
     - `Granblue::WikiFetcher` and `lib/tasks/fetch_wiki.rake` already stamp the column when it exists. Verify with specs for all three models.
     - Add stamping to `lib/tasks/jp_wiki.rake` (the JP column) and to wherever the batch-import preview persists `wiki_raw` (`app/controllers/concerns/batch_previewable.rb` and its callers).
   - **Blueprints:** add both dates to the weapon, summon and character blueprints' editor/full views.
